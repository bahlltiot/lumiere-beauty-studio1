# LUMIÈRE — сайт студии красоты

Премиальный сайт-визитка с онлайн-записью, личным кабинетом клиента и защищённой админ-панелью. Проект полностью рабочий: сервер, база данных, регистрация и авторизация, восстановление пароля, запись без двойных слотов, управление контентом и настройка бренда.

Демо-бренд: **LUMIÈRE — lash & brow atelier**, Москва. Все данные, тексты, фотографии, палитра и шрифты — демонстрационные и меняются под клиента.

## 1. Быстрый запуск

Требуется **Node.js 24 или новее** (рекомендуется 26). Внешние npm-зависимости не нужны — используется встроенный `node:sqlite`.

```bash
cd beauty-studio
npm run seed     # создаст data/lumiere.sqlite с демо-данными
npm start        # http://localhost:3000
```

Для разработки с автоперезапуском:

```bash
npm run dev
```

Адреса:

| Раздел | Адрес |
|---|---|
| Сайт | http://localhost:3000 |
| Онлайн-запись | http://localhost:3000/booking |
| Личный кабинет | http://localhost:3000/account |
| Админ-панель | http://localhost:3000/admin |
| Политика конфиденциальности | http://localhost:3000/privacy |

### Открытие сайта по ссылке для другого человека (демо)

Сервер слушает все сетевые интерфейсы (`HOST=0.0.0.0`), поэтому для устройства в той же локальной сети доступна ссылка вида:

```
http://<IP-вашего компьютера>:3000/
```

Пример для текущей машины: **http://192.168.1.5:3000/**

1. Узнайте IPv4-адрес: Windows — `ipconfig`, строка «IPv4-адрес» для адаптера Wi-Fi/Ethernet (например, `192.168.1.5`).
2. Остановите сервер и запустите его с явным адресом: `PORT=3000 HOST=0.0.0.0 npm start` (по умолчанию уже `0.0.0.0`).
3. Поделитесь ссылкой вида `http://192.168.1.5:3000/` с человеком из той же Wi-Fi сети — он откроет сайт в своём браузере (как новый посетитель, с демо-данными).
4. Личный кабинет и админку откроет тот, у кого есть demo-аккаунт; ссылки вида `/#` и сессии у каждого свои.

**Вне локальной сети** ссылка вида `localhost` не сработает — нужен туннель:

```bash
cloudflared tunnel --url http://localhost:3000
```

После запуска cloudflared выдаст публичную ссылку вида `https://xxxx.trycloudflare.com` — по ней сайт будет открываться у любого человека с интернетом.

## 2. Что умеет сайт

### Публичная часть
- Главная: hero, услуги, «Обо мне», галерея с фильтрами и лайтбоксом, отзывы, контакты с картой.
- Онлайн-запись в 4 шага: услуга → мастер → дата и время → данные и подтверждение. Свободные слоты строятся по расписанию, длительности услуги, занятости мастера и блокировкам.
- Регистрация, вход, восстановление пароля, личный кабинет с историей записей, отменой, избранным и сменой пароля.
- Отзывы: оставить может только авторизованный клиент, публикация — после модерации. Все демо-отзывы помечены как демонстрационные.
- Адаптивная вёрстка, доступные модальные окна, лайтбокс, тосты, состояния загрузки и пустые состояния.

### Админ-панель
- **Обзор**: записи на сегодня, ожидающие подтверждения, сумма, клиенты, рейтинг, ближайшие визиты.
- **Записи**: фильтры по статусу, дате и поиску; карточка записи; статусы `pending → confirmed → completed / canceled`.
- **Расписание**: 7 дней с часами работы; блокировки на день или интервал (выходные, обучение, личное время).
- **Услуги**: создание, редактирование, скрытие, удаление; цена, длительность, категория, фото, описание.
- **Мастера**: портрет, роль, опыт, биография, привязка услуг, скрытие.
- **Обо мне**: имя, роль, цитата, биография, подход, фото, образование, преимущества.
- **Галерея**: фото работ и студии, категории, скрытие.
- **Отзывы**: модерация, публикация, отклонение, удаление.
- **Клиенты**: база с поиском, количеством записей, суммой и последним визитом.
- **Бренд**: название, подпись, слоган, юридическое название, город, тексты hero, главное фото и логотип.
- **Контакты**: телефон, email, адрес, метро, график, карта, Instagram / Telegram / WhatsApp / VK.
- **Тема и шрифты**: готовые палитры или ручной выбор 11 цветов, шрифты заголовков и текста, живой предпросмотр.
- **Правила записи**: шаг слотов, минимальное время до визита, срок отмены, горизонт записи.
- **SEO**: title, description, ключевые слова.

## 3. Персонализация под клиента

Почти всё меняется без кода — в админ-панели. После сохранения изменения сразу применяются на сайте.

### Название, логотип, палитра
1. `/admin#brand` — название, подпись, слоган, тексты первого экрана, главное фото, логотип.
2. `/admin#theme` — выберите готовую палитру или задайте свои цвета; выберите шрифты. Кнопка «Вернуть сохранённое» отменяет несохранённые изменения.
3. `/admin#seo` — заголовок вкладки и описание для поиска.

### Услуги, мастера, расписание
1. `/admin#services` — добавьте услуги: название, короткое и полное описание, цена, длительность, категория, фото. Скрытая услуга исчезает с сайта и из записи, но остаётся в истории.
2. `/admin#masters` — добавьте специалистов и отметьте, какие услуги они выполняют. Если услуг не выбрано — мастер выполняет все.
3. `/admin#schedule` — задайте часы работы и блокировки. Слоты пересчитываются автоматически.
4. `/admin#booking` — настройте шаг слотов и правила отмены.

### Контент
- `/admin#about` — блок «Обо мне».
- `/admin#gallery` — фотографии работ; категории фильтров берутся из настроек.
- `/admin#reviews` — отзывы и модерация.
- `/admin#contacts` — адрес, телефон, карта, соцсети.

### Изображения
- Загружайте PNG, JPG или WebP до 4 МБ прямо в полях «Фотография» — файлы сохраняются в `data/uploads/` и раздаются с `/uploads/...`.
- Можно вставить внешнюю ссылку `https://...`.
- Демо-фото по умолчанию загружаются с внешнего CDN. Для полностью локального сайта замените их своими через админку.
- `scripts/fetch-demo-photos.mjs` — необязательный скрипт, который скачивает демонстрационные фотографии в `public/assets/img` (удобно, если нужен офлайн-набор исходников).

### Демо-данные и сброс
Исходные данные лежат в `config/site.config.js` и применяются только при создании пустой базы. Чтобы вернуться к демо-состоянию:

```bash
# остановите сервер
rm data/lumiere.sqlite data/lumiere.sqlite-wal data/lumiere.sqlite-shm
npm run seed
npm start
```

> На Windows: удалите `data\lumiere.sqlite*` в проводнике или командой `Remove-Item`.

## 4. Переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости измените:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | Порт HTTP-сервера | `3000` |
| `HOST` | Интерфейс прослушивания | `0.0.0.0` |
| `DATA_DIR` | Папка базы и загрузок | `./data` |
| `COOKIE_SECURE` | `1` — cookie только по HTTPS | `0` |
| `DEMO_RESET_LINK` | `0` — не показывать ссылку восстановления | `1` |
| `TZ` | Часовой пояс расчёта слотов | системный |

`SESSION_SECRET` в `.env.example` оставлен как задел: текущие сессии хранятся в базе и не требуют подписи.

### Восстановление пароля
В демо-режиме после запроса ссылка показывается прямо в интерфейсе (`DEMO_RESET_LINK=1`), письмо не отправляется. Для production:
1. Поставьте `DEMO_RESET_LINK=0`.
2. Подключите почтовый сервис (SMTP/API) в `server/api.js` в обработчике `POST /api/auth/forgot` — токен уже создаётся и хранится в базе.
3. Проверьте, что ссылка ведёт на `https://ваш-домен/account.html?reset=...`.

## 5. Публикация на хостинге

Подойдёт любой VPS с Node.js 24+ (Timeweb, Beget, Reg.ru, Hetzner, Selectel). Статический хостинг без Node не подойдёт: нужны API и SQLite.

### Бесплатный хостинг: Render (рекомендуется для демо)

В репозитории есть готовый `render.yaml` (план Free, Node 22, порт 3000):

```yaml
services:
  - type: web
    name: lumiere-beauty-studio
    runtime: node
    plan: free
    buildCommand: ""
    startCommand: node server/index.js
    envVars:
      - key: NODE_VERSION
        value: 22
      - key: DATA_DIR
        value: /var/data/lumiere
      - key: DEMO_RESET_LINK
        value: "0"
      - key: COOKIE_SECURE
        value: "1"
      - key: TZ
        value: Europe/Moscow
```

Как задеплоить:

1. Загрузите репозиторий на GitHub.
2. В Render: **New → Web Service → Connect your repo** (база `beauty-studio`).
3. Render подхватит `render.yaml`; план — Free.
4. После деплоя доступ будет по адресу `https://lumiere-beauty-studio.onrender.com`.

Ограничения бесплатного тира Render: эфемерная файловая система (SQLite не персистентен между деплоями) и спиндаун сервиса после бездействия. Для демо-проекта это приемлемо.

### Вариант с VPS (systemd / Nginx) — см. ниже.

### Вариант с systemd

```ini
# /etc/systemd/system/lumiere.service
[Unit]
Description=LUMIERE beauty studio
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/lumiere
Environment=NODE_ENV=production
Environment=PORT=3000
Environment=HOST=127.0.0.1
Environment=DATA_DIR=/var/lib/lumiere
Environment=COOKIE_SECURE=1
Environment=DEMO_RESET_LINK=0
Environment=TZ=Europe/Moscow
ExecStart=/usr/bin/node server/index.js
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /var/lib/lumiere
sudo chown www-data:www-data /var/lib/lumiere
sudo systemctl enable --now lumiere
```

### Nginx + HTTPS

```nginx
server {
  listen 80;
  server_name example.com www.example.com;
  return 301 https://$host$request_uri;
}

server {
  listen 443 ssl http2;
  server_name example.com www.example.com;

  ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

  client_max_body_size 6m;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

Сертификат: `sudo certbot --nginx -d example.com -d www.example.com`.

После публикации:
- замените домен в `public/robots.txt` и `public/sitemap.xml`;
- замените тексты политики конфиденциальности на реквизиты клиента;
- проверьте `COOKIE_SECURE=1` и HTTPS;
- смените демо-пароли и создайте своего администратора;
- сделайте резервную копию `DATA_DIR`.

### Резервные копии

Остановите сервис и скопируйте папку `DATA_DIR` целиком (база `lumiere.sqlite`, файлы `-wal`/`-shm` и `uploads/`). Для регулярных бэкапов без остановки используйте `sqlite3 .backup` или snapshot диска. Файлы загрузок входят в ту же папку.

## 7. Безопасность

- Пароли хранятся как `scrypt$salt$hash`, сессии — только в виде хеша токена.
- Раздельные сессии клиента (`lum_session`) и администратора (`lum_admin`), cookie `HttpOnly`, `SameSite=Lax`, опционально `Secure`.
- Проверка `Origin` для изменяющих запросов, rate limit на вход, регистрацию и восстановление пароля.
- CSP без inline-скриптов, `X-Frame-Options`, `nosniff`, ограничение загрузок 4 МБ и допустимых MIME.
- Админ-маршруты требуют сессию администратора; публичный API не отдаёт персональные данные.
- SQL-запросы параметризованы.

Ограничения демо: нет отправки email/SMS, нет интеграции с платёжными системами, ссылка восстановления показывается на экране. Для production подключите почтовый сервис и, при необходимости, внешнюю БД.

## 8. Проверка перед сдачей

1. Регистрация нового клиента → вход → запись на свободный слот.
2. Повторная запись на тот же слот → должна быть ошибка «время занято».
3. Отмена записи в кабинете → слот снова доступен.
4. Восстановление пароля → ссылка → новый пароль → вход.
5. Вход в админку → подтверждение записи → статус меняется у клиента.
6. Добавление/редактирование услуги и мастера → изменения видны на сайте и в записи.
7. Блокировка времени → слот исчезает из записи.
8. Смена темы, бренда и контактов → обновите сайт, проверьте применение.
9. Загрузка фото → появляется в галерее.
10. Модерация отзыва → публикация на главной.

### Полезные проверки через API

```bash
curl http://localhost:3000/api/site
curl -i http://localhost:3000/api/admin/overview          # 401 без сессии
curl -i http://localhost:3000/does-not-exist              # 404
```
